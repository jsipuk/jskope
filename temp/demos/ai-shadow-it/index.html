How Netskope Identifies Personal vs Corporate AI Instances

Authentication Tenant Detection

Netskope inspects the authentication flow when a user logs into an AI tool. A corporate Claude for Work login goes through an enterprise SSO (Okta, Entra ID) — a personal login uses the standard claude.ai authentication. Netskope identifies the tenant context and applies different policies to each.

CASB App Instance Classification

For major AI tools, Netskope maintains instance-level classification: "ChatGPT Personal," "ChatGPT Team," "ChatGPT Enterprise" are treated as distinct applications with different CCI scores and policy applicability. Personal instances can be blocked while corporate instances are allowed and monitored.

Prompt Inspection — Inline DLP

Regardless of which AI tool is used, Netskope's inline DLP inspects every prompt before it reaches the model. PII, financial data, credentials, PHI, source code — all matched against DLP profiles. A block stops the data leaving; a coaching notification explains the policy to the user in real time.

Unsanctioned App Detection

Tools like Poe, Perplexity, Character.ai, and local AI interfaces (Ollama web UI) are automatically scored against the Cloud Confidence Index. Low-CCI AI apps can be blocked entirely, or allowed with logging and DLP enforcement applied to all interactions.

The rules behind these scenarios in your policy: switching to a personal/unsanctioned AI is stopped by [Demo] Block Unsanctioned AI → Block; a sensitive prompt into any monitored AI hits [Demo] Block Sensitive Data Upload to Gen AI (DLP-PII/PCI/SourceCode) → Block; and using a non-corporate ChatGPT instance is caught by Block Access to non-approved ChatGPT (Non-Corp Instance) → Block. Sanctioned corporate AI stays allowed and coached.
