1

Access a Personal Cloud Storage Site

The employee navigates to personal file-sharing services not sanctioned by the organisation.

ACTIVE
A user opens a browser and navigates to a personal Dropbox or WeTransfer account — services not covered by IT policy. The intent is to move files outside corporate controls.
Prerequisite: Netskope Client must be active. If not, these sites open normally without any controls firing.
Open Dropbox (Personal) Open WeTransfer Open MEGA
Expected Netskope Response
If unsanctioned cloud storage is blocked by policy: you'll see a Netskope block page with the policy name and category. If coaching is configured: a real-time in-browser notification appears explaining why personal cloud storage violates acceptable use. If only logged: the access event appears in the Netskope console under CASB activity.
2

Download a Synthetic Sensitive File

Download a synthetic data file that contains PII, credit card numbers, or employee records.

WAITING
The user downloads an employee records file from a shared drive — the kind of data that should never leave the corporate perimeter unscanned.
Download Employee Records (PII) Download Payment Data (PCI) More DLP scenarios →
Expected Netskope Response — DLP
Netskope performs inline content inspection of the downloaded file. If a DLP profile matches PII patterns (SSNs, names, addresses), the download is blocked or quarantined and an incident is raised. The file contains clearly labelled synthetic test data — safe to use in demos.
3

Attempt to Email Sensitive Data Externally

Try sending the file or pasting the sensitive content via a personal webmail account.

WAITING
The employee opens Gmail or Outlook.com and attempts to compose an email attaching the file or pasting the employee record data directly into the message body.
Open Gmail (Personal) Open Outlook.com Open ProtonMail
Expected Netskope Response
If personal webmail is blocked by SWG policy: a block page appears when navigating to Gmail or Outlook.com. If coaching is configured: the user receives an in-browser notification about acceptable use. If webmail is allowed but DLP is active: attaching the sensitive file or typing PII into the compose window triggers an inline DLP alert and the upload is blocked before submission.
4

Review the Netskope Audit Trail

In the Netskope console, navigate to the events log to see every action captured throughout this series.

WAITING
Now switch to the Netskope tenant console. Every step above — the CASB access event, the DLP file download alert, the blocked webmail upload — appears in the audit log with full metadata: user identity, device, timestamp, policy matched, and action taken.
Open Netskope Console
What to Look For in the Console
Navigate to Skope IT → Events. Filter by your username and the past 15 minutes. You should see: (1) CASB access events for Dropbox/WeTransfer with the app's CCI score, (2) DLP incidents for the downloaded PII file, (3) SWG block/coaching events for personal webmail. Every event links to full session detail and the matched policy rule.

Series Complete — Key Takeaways

You've demonstrated the full insider threat kill chain: an employee accesses unsanctioned cloud storage, downloads sensitive data, and attempts to exfiltrate via personal email. Netskope intercepts at every stage — CASB identifies shadow IT usage, DLP blocks sensitive file movement, SWG controls personal webmail — and creates a full audit trail without requiring any endpoint agents beyond the Netskope Client.
