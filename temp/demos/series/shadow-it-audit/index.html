Visit an Unsanctioned File-Sharing Application

Navigate to a file-sharing or collaboration app outside the organisation's approved cloud catalogue.

ACTIVE
An employee uses a personal WeTransfer or MEGA account to share files with a third party — bypassing the IT-approved channels. Netskope CASB detects the access, scores the app against its Cloud Confidence Index, and logs the activity.

Visit WeTransfer (CCI 42) Visit MEGA (CCI 22) Visit Filebin (CCI 33)
Expected Netskope Response — CASB Discovery
Netskope logs the access event in real time under CASB App Discovery. The app is classified against 50+ criteria and scored on the Cloud Confidence Index (0–100). Low-CCI apps may be blocked, coached, or allowed with logging depending on your policy. The Netskope console shows the app name, CCI score, user identity, and access timestamp.
2

Download a Synthetic Sensitive Document

Download one of the synthetic data files below. This simulates retrieving a sensitive document from an unapproved cloud source.

WAITING
The employee retrieves an employee records file from the unsanctioned service. Netskope performs inline content inspection of the download — comparing the file contents against DLP profiles before it reaches the device.
Download: Employee Records (PII) Download: Payment Data (PCI) Download: API Credentials
Expected Netskope Response — DLP Inline Inspection
Netskope inspects the file download inline. If DLP profiles match PII patterns (SSN, names, addresses, credit card PANs), the download is blocked before it reaches the filesystem — or a DLP incident is raised for review. The console shows the file name, matched profile, user identity, and the unsanctioned app it was downloaded from.
3

Attempt to Re-upload via Personal Dropbox

Open a personal Dropbox account and attempt to upload the downloaded file. This simulates the final exfiltration step.

WAITING
The employee opens their personal Dropbox to re-upload the file — planning to access it from a personal device later. Netskope intercepts the upload, inspects the content inline, and fires DLP controls even though the destination is a different cloud app from the source.
Upload Destination CCI Score Expected Policy
Dropbox (Personal) 69 — General COACH
OneDrive (Personal) 65 — General COACH
MEGA 22 — Poor BLOCK
Pastebin 38 — Low BLOCK
Open Personal Dropbox Open OneDrive Personal
Expected Netskope Response — DLP Upload Block
Netskope inspects the file upload inline as the content leaves the device. If the previously downloaded file contains PII or financial data, the upload is blocked even if the destination app (e.g. Dropbox) would otherwise be accessible. The block occurs at content level — not just at the app level — demonstrating that CASB controls follow the data, not just the destination.

Series Complete — Key Takeaways

You've walked through the full shadow IT risk lifecycle: an employee accessing low-trust unsanctioned apps, downloading sensitive data, and attempting to move it across cloud services. Netskope's CASB discovers every unsanctioned app in real time and scores it against the Cloud Confidence Index. DLP intercepts sensitive data inline — whether it's a download from MEGA or an upload to Dropbox — creating a complete audit trail without needing to pre-approve every app.
